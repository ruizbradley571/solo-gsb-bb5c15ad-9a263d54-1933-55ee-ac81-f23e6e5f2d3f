# 首命中规则审计台（First-Hit Rule Audit Console）

一款**完全本地运行**的访问控制规则审计工具。规则按自上而下的顺序求值、**首条匹配即生效**；
本工具精确计算每条规则在该语义下**实际可达的流量区域**，识别被前序规则遮蔽的部分，
即使该遮蔽由**多条规则的并集共同覆盖**造成也能识别，并为每个问题给出**可复现的示例报文**与**遮蔽来源**。
此外，「无损精简」面板可对每条规则**模拟删除**，逐条核对其原有效流量在删除后是否仍由后续规则以
**相同动作**接管（未命中单独计为一种结果），只有所有报文最终动作都不变时才建议删除。
「策略回归样例生成器」面板则为当前规则集生成一组**紧凑的回归测试报文**：每条实际可达规则
至少被首命中一次、每组「首命中规则阻挡后续规则」的关系至少被见证一次。
「流量样本归因」面板支持粘贴**带权重的流量样本**（唯一 id × 源 IP × 源端口 × 协议 × 正数权重），
按当前规则逐条执行首命中判定，按命中规则 / 动作 / 未命中汇总权重与占比。

- 技术栈：React 18 + TypeScript + Vite + [ipaddr.js](https://github.com/whitequark/ipaddr.js)
- 纯前端应用，无后端，所有分析都在浏览器内完成，规则数据不外传
- 规则维度：**源 IPv4 CIDR × 源端口区间 × 协议（TCP / UDP / ANY）× 动作**

## 一条命令启动

### 方式一：Docker Compose（推荐）

```bash
docker compose up -d --build
```

启动后访问：

> **http://localhost:8080**

页面布局：上方为规则列表，中部为「策略目标验证」「无损精简」「策略回归样例生成器」与「流量样本归因」面板，下方为审计结果。

停止：

```bash
docker compose down
```

### 方式二：Docker

```bash
docker build -t first-hit-rule-audit .
docker run --rm -p 8080:80 first-hit-rule-audit
```

访问地址同上：**http://localhost:8080**

### 方式三：Node 本地开发

```bash
npm install
npm run dev        # 开发模式，热更新
# 或
npm run build && npm run preview   # 生产构建后本地预览
```

开发模式访问 **http://localhost:5173** ，预览模式访问 **http://localhost:4173** 。

## 功能说明

### 规则编辑与拖拽排序

- 在表格中直接编辑规则名称、CIDR、端口区间、协议、动作
- 拖拽行首的 ⠿ 手柄（或整行）即可调整顺序；顺序就是匹配优先级
- 「启用」列可勾选 / 取消勾选：**停用的规则合法但不参与任何首命中分析**
  （效果等同于暂时移除，列表中标灰、审计结果标为「停用」），在无损精简中也不会被模拟删除
- 支持新增、复制、删除、一键清空、恢复内置演示规则

### 调序影响预览（拖拽后先预览、再确认）

拖拽松手后**不会立即改动规则顺序**，而是先弹出「调序影响预览」：
工具分别用**当前顺序**与**候选顺序**执行同一份审计，并**按规则 id 对齐**两份结果。

弹窗内容：

1. **受影响规则表**：逐条列出旧/新序号、状态（旧 → 新）、有效报文空间（旧 → 新）
   及变化量（绿色 `+` 增加 / 红色 `−` 减少）。仅位置移动、审计结果不变的规则标注
   「仅序号变化」；序号未变但因其它规则上下移动而被影响的规则同样会列出。
2. **首命中动作发生变化的流量**：每一组都给出至少一个**可复现样例报文**
   （`协议 src=IP:端口`，可一键复制），并标明变更前后命中的规则序号、名称、动作，
   以及该组影响的报文空间大小。
3. **仅易主、动作不变的流量**：首命中规则改变但动作一致，单独分组列出供参考。
4. **无实际差异时明确提示**：候选顺序下状态、有效空间、每个报文的首命中结果都不变时，
   顶部给出绿色提示；仍可选择「仍要应用该顺序」或直接取消。

点击「确认应用候选顺序」后规则才一次性重排并刷新审计；
点击「取消」（或点遮罩 / 按 Esc 区域）则**保持原顺序**。
**非法规则继续按既有语义排除**：不参与首命中计算，仅在表中展示其序号变化。

### 首命中可达性审计

规则求值采用与真实 ACL 相同的语义：对任意一个报文（源 IP、源端口、协议），
**列表中第一条覆盖它的规则生效**，其后覆盖同一报文的规则对该报文永远不可达。

工具把全部规则声明的 CIDR 递归切割成互斥的 IP 原子块、把端口区间切成互斥的端口原子段，
连同协议维构成离散报文单元，逐个单元登记其“首个命中者”，从而精确得出每条规则：

| 状态 | 含义 |
| --- | --- |
| **可达** | 声明区域全部在首条命中语义下归本规则 |
| **部分遮蔽** | 一部分区域被上方规则夺走，其余仍可达；展开可见“实际可达区域” |
| **完全遮蔽** | 声明区域内的任何报文都先命中其它规则，本规则永不生效 |
| **非法** | CIDR / 端口 / 协议 / 动作校验失败，**不参与分析**（其它规则的审计不考虑它） |

- **共同覆盖识别**：当规则 R 的区域没有被任何**单条**前序规则独立完全遮蔽，
  但被前序规则的**并集**完全覆盖时（例如两条各盖一半 `/25` 的规则盖住一条 `/24`），
  R 仍被判定为完全遮蔽，并标注 **“共同覆盖”** 徽章，同时列出全部参与来源。
- **遮蔽来源**：逐条列出遮蔽了本规则的上方规则（名称、动作、贡献单元数，按贡献排序）。
- **可复现示例报文**：
  - *可达样例*：一个实际命中本规则的报文；
  - *遮蔽样例*：一个看似属于本规则、实际命中前序规则的报文，并注明命中的规则编号、名称与动作。
  - 报文形如 `TCP src=192.168.1.10:22`，可一键复制。

### 实际可达区域展示

展开部分遮蔽的规则，可以看到其有效区域按协议合并后的精确表达：

- 一组规范 CIDR（相邻原子块会自动合并回更大的 CIDR）
- 一组合并后的端口区间
- 该区域的报文空间大小（IP 数 × 端口数）

### 策略目标验证（只读）

**面板入口**：打开 http://localhost:8080 后，页面中部「策略目标验证」面板（规则列表之下、
「无损精简」面板与审计结果之上）。
它回答一个问题：**目标空间里的报文，按当前规则首条命中后，动作是否符合期望？**

输入目标 IPv4 CIDR、端口区间、协议（TCP / UDP / ANY）与期望动作，点击「执行验证」。
验证是**只读**的，不改动任何规则；非法规则与审计一致地被排除（不参与首命中计算），
协议 ANY 会**分别检查 TCP 与 UDP** 并给出分协议统计。

结果按首命中语义精确覆盖整个目标空间，分为三类，各自给出报文空间大小与占比：

| 分类 | 含义 |
| --- | --- |
| **符合期望** | 首命中规则的动作 === 期望动作 |
| **命中其他动作** | 首命中规则存在但动作不同，按实际动作分组汇总 |
| **未命中任何规则** | 目标区域没有任何合法规则覆盖 |

- **违规明细**：每个实际动作分组与未命中分组都给出**可复制的代表报文**
  （每个具体协议一个，形如 `TCP src=10.0.0.1:22`，可一键复制）与**精确的 CIDR / 端口区域**。
  区域按「协议 → 连续端口段 × 规范 CIDR 列表」逐行展开，不做 IP 集合 × 端口集合的
  笛卡尔积近似，行大小合计与逐单元统计精确一致。
- **目标边界精确切分**：目标 CIDR / 端口边界会追加进原子切分，即使落在既有原子块
  内部也能正确切开，分类与区域输出不受影响。
- **自动刷新**：规则编辑或调序确认后，验证结果自动按最新规则重算；
  修改目标输入后需再次点击「执行验证」。

### 无损精简（模拟删除，动作不变才建议）

**面板入口**：「策略目标验证」与「审计结果」之间的「无损精简（模拟删除，动作不变才建议）」面板。
点击「分析」后，工具**逐条、独立地**模拟删除每一条**已启用、合法且当前有有效流量**的规则
（停用、非法、完全遮蔽无有效流量的规则直接跳过并计数说明），全程只读，不改动规则。

对每个候选规则，删除模拟与审计在**同一套 IPv4 原子块 × 端口原子段 × 协议离散单元空间**中进行
（删除一条规则不会重新切分原子，单元在删除前后天然一一对齐）：

1. 取该规则在当前顺序下的全部**首命中（有效）单元**；
2. 对每个单元，查找删除该规则后**位于其后的第一条仍覆盖它的规则**
   （更靠前的规则若覆盖它，该单元原本就不会归本规则）；
3. 若后面没有任何规则覆盖，该单元变为**「未命中任何规则」——未命中被当作一种独立的比较结果**，
   不按任何默认动作假设；
4. **只有该规则的全部有效单元删除后仍得到相同最终动作**（每个单元都被某条后续规则以与本规则
   **相同的动作**接管），才列为「可安全删除」；否则列出动作会改变（含变为未命中）的精确冲突区域。

判定基于逐单元的精确比较，**不使用覆盖比例推断**：哪怕只差一个单元的动作不同，整条规则也不会被建议删除。

每条建议展开后给出：

- **接管规则与精确区域**：原有效流量被哪些**后续规则**接管，按接管规则分组，
  每组给出精确的「协议 → 连续端口段 × 规范 CIDR 列表」区域（非矩形区域逐行展开，
  不做笛卡尔积近似）、接管报文空间大小与原子单元数；各组区域互斥、合计精确等于该规则的有效流量。
- **动作与可复制代表报文**：每组标注接管动作（安全候选与被删规则一致）并给出确定性的代表报文
  （形如 `TCP src=10.0.0.1:80`，一键复制），报文可直接复现删除后的首命中结果。
- **不可安全删除的原因**：不安全候选同样展开，区分「被后续规则以不同动作接管」与
  「删除后未命中任何规则」两类冲突，各自附精确区域与代表报文。

**单条预览确认删除**：在「可安全删除」卡片中点击「删除该规则（动作无损）」会弹出二次确认，
汇总规则声明、接管规则表与代表报文；确认后才真正删除该一条规则。面板**不提供批量删除**，
且每次删除后其余建议都需要重新分析。

**过期保护**：分析结果记录分析时刻的规则快照；一旦规则被**编辑、调序确认或删除**，旧分析立即标记为
**已过期**：顶部出现红色过期提示，所有删除按钮（含确认弹窗中的确认按钮）禁用，必须重新点击
「重新分析」后才能再次应用建议，避免把过期结论套用到新规则上。

### 策略回归样例生成器

**面板入口**：「无损精简」与「审计结果」之间的「策略回归样例生成器」面板。
它为当前规则集生成一组**紧凑的回归测试报文**，用于回归验证「首条命中」行为是否符合预期。
生成在与审计**完全相同**的原子空间（合法且启用规则的 IPv4 原子块 × 端口原子段 × 协议）上进行，
非法与停用规则按既有语义排除，全程只读、不改动规则。

**覆盖目标**（两类，全部来自同一原子空间的精确首命中归属）：

1. **首命中目标**：每条**实际可达**（拥有首命中单元）的规则，至少被一个样例报文首命中一次；
   完全遮蔽的规则永不生效，不属于可达目标。
2. **阻挡见证目标**：每一组「首命中规则 b 阻挡后续规则 s」的关系（存在某个报文首命中 b、
   且 s 的声明区域也覆盖它），至少被一个样例报文见证一次——该报文看似属于 s，实际命中 b。

**确定性贪心生成**：一个候选报文可同时覆盖多个目标（它首命中的规则 + 它见证的全部阻挡关系）。
每轮选取**覆盖尚未覆盖目标数最多**的候选报文，并列时按**协议（TCP < UDP）/ IP / 端口升序**
取最小者，直到全部目标被覆盖。每个目标按构造都至少有一个见证报文，因此必然全覆盖；
同一规则集多次生成的结果完全一致，可安全纳入回归基线。

每条样例展示：**报文**（形如 `TCP src=10.0.0.1:80`，可一键复制）、**预期命中规则**（序号与名称）、
**动作**，以及它**覆盖的目标清单**（首命中 / 阻挡见证，阻挡见证标明「谁阻挡谁」）。
面板底部的「覆盖目标清单」可展开核对每个目标由哪条样例覆盖。

- **复制 / 下载 JSON**：导出包含统计摘要、全部覆盖目标（含见证样例序号）与样例集的 JSON，
  支持复制到剪贴板或下载为 `.json` 文件。
- **无有效规则时明确提示**：没有合法且启用的规则时，面板明确提示无法生成，并说明如何恢复
  （新增规则、修正非法规则或勾选「启用」）。
- **过期保护**：生成结果记录生成时刻的规则快照；规则被**编辑、调序确认或启停**后，
  旧结果立即标记为**已过期**，复制与下载按钮禁用，必须「重新生成」后才可导出。

### 流量样本归因

**面板入口**：「策略回归样例生成器」与「审计结果」之间的「流量样本归因」面板。
它回答另一个问题：**一批实际流量样本，按当前规则首条命中后，各自落到哪条规则、什么动作上？**

粘贴样本 JSON 数组后点击「执行归因」。每条样本须为
`{ "id", "srcIp", "srcPort", "protocol", "weight" }`：

- **id**：非空字符串或数字，全数组唯一（重复即报错，错误行的 id 也参与查重）；
- **srcIp**：严格点分十进制 IPv4（不接受缩写写法）；
- **srcPort**：0–65535 的整数；
- **protocol**：`TCP` / `UDP` / `ANY`（大小写不敏感）；
- **weight**：正数（支持小数与数字字符串）。

判定语义与审计一致：仅**合法且启用**的规则参与首命中计算（非法 / 停用规则排除并计数说明）。
**ANY 样本按同一权重分别判定 TCP 与 UDP**——一条样本产生两条判定记录，
二者可能命中不同规则而落入不同分组；总权重为全部判定记录权重之和。

结果展示：

- **汇总统计**：合法样本数 / 判定条数、总权重、命中与未命中的权重及占比；
- **归因分组**：按命中规则（序号、名称、动作）分组汇总权重与占比，按权重降序排列，
  **未命中任何规则**的分组固定列于最后（红色标记）；
- **样本明细**：每组可展开，组内判定记录按**权重降序**（同权重按行号）列出，
  含原始行号、id、具体协议报文与权重占比；
- **逐行报错**：重复 id 或非法字段逐行列出（一行可多个错误），**错误行不计入统计**，
  其余合法样本照常归因；
- **过期保护**：规则被编辑、调序或启停后旧结果标记为已过期；样本输入修改后也会提示需重新执行。

### JSON 导入

点击「粘贴 JSON 导入」，支持三种形态：

```json
[
  { "name": "允许内网 Web", "cidr": "10.0.0.0/8", "portStart": 80, "portEnd": 443,
    "protocol": "TCP", "action": "allow" }
]
```

```json
{ "rules": [ { "cidr": "0.0.0.0/0", "portStart": 0, "portEnd": 65535,
               "protocol": "ANY", "action": "deny" } ] }
```

也可以直接粘贴本工具**导出的审计报告**（`{ "entries": [...] }`）回填规则。

可选择“替换全部规则”或“追加到现有规则”。字段缺失时按空值处理；
**非法 CIDR / 端口不会导致导入失败**，该规则会保留在列表中并标记为非法、不参与分析。

### 导出审计结果

点击「导出审计结果」，得到包含统计摘要与每条规则完整审计明细的 JSON
（状态、声明/有效报文空间、可达区域、遮蔽来源、共同覆盖标记、示例报文、非法原因等），
支持复制到剪贴板或下载为 `.json` 文件。「导出规则」则只导出可再次导入的规则数组。

## 校验规则（非法项不参与分析）

- **CIDR**：必须是规范的 IPv4 CIDR —— 点分十进制四段、每段 0–255、前缀 0–32、
  主机位必须为零（`10.0.0.5/24` 会被拒绝，并提示规范写法 `10.0.0.0/24`）；
  不接受 IPv6、缩写地址（如 `10.0.0/8`）。
- **端口**：起止均为 0–65535 的整数，且起始 ≤ 结束。
- **协议**：`TCP` / `UDP` / `ANY`（大小写不敏感，导入小写 `tcp` 也可识别）。
- **动作**：非空文本（如 `allow` / `deny`，可自定义）。

非法规则以红色标出并展开列出原因；它们被排除在遮蔽分析之外，
即一条非法规则不会遮蔽后面的任何规则。

**停用规则**（列表中取消勾选「启用」）同样不参与原子空间构建与首命中计算，
在审计结果中以灰色「停用」条目展示；重新勾选即恢复参与分析。
非法与停用规则都会被无损精简跳过。

## 工作原理（简要）

1. 校验全部规则，分离合法 / 非法规则（非法规则不进入后续步骤）。
2. 以 `0.0.0.0/0` 为初始块，把每条合法规则的 CIDR 递归二分插入，
   得到一组两两互斥、按 CIDR 对齐的 **IP 原子块**；端口维同理取所有区间端点形成**端口原子段**。
3. 单元空间 = IP 原子块 × 端口原子段 × {TCP, UDP}（`ANY` 同时占据两种协议）。
4. 按规则顺序遍历，每个单元登记第一个覆盖它的规则（owner）；
   后续规则若声明了该单元，则该单元记为被遮蔽，并记录遮蔽来源。
5. 汇总每条规则的声明/有效报文空间、状态、遮蔽来源；
   将其有效单元合并成规范 CIDR 与端口区间；选取确定性的代表单元生成示例报文。

单元数量受规则中不同 CIDR / 端口边界数量约束（数十条规则量级为数百到数千单元），
因此在浏览器中可以即时完成。

**调序预览**只是把同一套审计对候选顺序再跑一遍：由于规则集合不变，IP / 端口原子
划分与顺序无关，两次结果共享同一套原子空间，因此可以逐单元比较首命中归属（按规则 id），
精确得到归属转移、动作变化分组及确定性的可复现样例。

**策略目标验证**复用同一套原子空间：把目标 CIDR / 端口边界一并插入原子切分后，
逐单元查询首命中者，按「符合期望 / 命中其他动作（按实际动作分组）/ 未命中任何规则」
归类并累计报文空间；违规区域按 协议 → 连续端口段 → 规范 CIDR 列表 精确展开
（相邻且 IP 集合相同的端口原子合并为一行），代表报文取各分组扫描序首个单元，
因此样例确定、可复现，区域行合计与逐单元统计精确一致。

**无损精简**同样不重新切分原子：删除一条规则只是原子空间的规则子集，
全部单元 key 在删除前后完全对齐。对被删规则 R 的每个首命中单元，删除后向下扫描
R 之后的规则找第一个接管者；没有接管者即独立记为「未命中」。仅当每个单元的接管者动作
都与 R 相同（且不存在未命中单元）时才判为可安全删除。接管 / 冲突流量按接管规则分桶，
复用与目标验证相同的精确区域构建（协议 → 端口段 × CIDR 行，非矩形区域逐行展开），
代表报文取桶内字典序最小单元，确定且可复现。

**策略回归样例生成器**复用同一套原子空间与首命中归属：每个有主单元天然是一个候选报文，
它覆盖「其首命中规则的首命中目标」以及「它作为见证的全部 (首命中规则, 后续声明规则) 阻挡关系」。
贪心每轮扫描全部候选，选取未覆盖目标数最多者（并列按协议 / IP / 端口升序），
选中后把新覆盖目标从所有候选的计数中移除，直到目标清零；候选按报文（协议, IP, 端口）
预排序，因此首个达到最大计数者即为平局中的最小者，结果确定、可复现。
